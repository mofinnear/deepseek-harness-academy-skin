# 代码审查说明（给 DeepSeek / GPT 等审查者）

> 审查包只有代码和说明，不含图片素材和构建产物，**不能用来安装**；README 里的预览图链接和安装命令在审查包里无效，属于预期情况。

请审查「星海书院」皮肤插件的代码，找出 **bug、安全隐患、会误删或损坏用户数据的地方、跨平台问题、性能问题**。下面先介绍项目，再列出审查重点和已知的有意设计（避免误报），最后是希望的输出格式。

## 一、这是什么

- DeepSeek Harness 是一个 Electron 桌面应用（macOS / Windows）。本项目是它的**本地客户端插件**，只改界面外观：全窗口背景、金边面板、右侧角色陪伴栏（四个表情可切换）等。**不修改应用本体和签名。**
- 安装只写用户目录的两处：`~/.dsh/profiles/desktop/node_modules/@local/dsh-logo/`（插件文件）和 `~/.dsh/profiles/desktop/cordis.patch.yml`（追加一条加载项，4 行 YAML）。Windows 上 `~` 是 `%USERPROFILE%`。
- 运行时：应用启动时加载 `brand-override/index.js`（宿主端，只打一行日志）和 `dist/client.js`（浏览器端，由 `tools/build.mjs` 把 `client.js` + 两份 CSS + 图片内联生成，约 6.8 MB，**不用审**）。
- 插件**不发任何网络请求**；只用 `localStorage` 记住皮肤开关、表情、显示模式三项设置。

## 三、请重点检查

1. **安装 / 卸载脚本**
   - 改动前是否一定先备份；备份失败时是否会停下。
   - 重复安装会不会重复追加加载项；卸载是否**只**删掉安装时追加的那几行，`cordis.patch.yml` 的其他内容（包括末尾换行、Windows 的 `\r\n`）是否完全不动。
   - 路径里有空格、中文用户名、设置了 `DSH_HOME` 环境变量时是否正常。
   - `cordis.patch.yml` 不存在、插件目录已存在（旧版）等边界情况。
   - Windows：PowerShell 5.1 语法、`$ErrorActionPreference = 'Stop'` 下的错误处理、`.bat` 调用 `-ExecutionPolicy Bypass` 是否合适、编码问题。
2. **client.js**
   - `MutationObserver` 监听整个 `document.body` 的子树变化：回调里的工作量是否会拖慢应用（会话很长、流式输出时）。
   - 定时器、事件监听是否会泄漏；快速连点表情、快速切换皮肤时是否会出错或留下多余元素。
   - 关闭皮肤（切回「原版」）后是否完全还原：主题偏好、侧栏文案、注入的元素和样式。
   - `localStorage` 读写都包了 `try/catch` 吗。
3. **CSS**：会不会盖住应用原生的弹出菜单、对话框（层级约定：背景 0 < 对话列 1 < 侧栏 10 < 陪伴栏 12 < 原生顶栏 15 < 全屏右侧面板 18 < 原生弹出层 20）；有没有依赖会变的哈希类名之外更脆弱的写法。
4. **使用说明**里给 AI 助手的命令：会不会在某些情况下误删或覆盖用户文件。

## 四、已知的有意设计（不是 bug）

- 用 `setTimeout` 而不是 `requestAnimationFrame`：窗口在后台时 rAF 不触发，会让表情切换、淡入卡住。
- 表情切换是**直接替换**图层再加「往上顶 3px + 星光」动画，不做交叉淡入（交叉淡入会出现重影，用户明确不要）。
- 星光元素 800ms 后由定时器删除；新图层是克隆旧图层后去掉动画类和星光再插入的（为了每次切换动画都从头播放）。
- 输入框高度在 `MutationObserver` 回调里**不经防抖**立即测量（切换会话时输入框会被应用整个换掉，晚测会让金边缩一下）。
- 选择器尽量用 `data-slot`、`data-*`、`role`、`:has()`；`[class*="_sidebarCol"]` 这类按类名片段匹配是少数例外，应用改版后可能要调整。
- 非 Mac 桌面版（`html[data-platform]:not([data-platform="darwin"])`）陪伴栏下移 40px，给 Windows 窗口右上角的按钮条让位（按应用代码推断，未实机验证）。
- 插件目录里的 `.academy-install` 是安装记录（`added_row` 加载项是不是这次加的、`previous_plugin` 安装前那里另有插件时它的备份位置、`created_patch` 配置文件是不是这次新建的），卸载靠它还原到安装前的状态。旧版装的没有记录，升级时从最近一份「装皮肤之前」的备份推断。新插件先在同目录的 `.dsh-logo-staging-<进程号>` 里准备好再一次换上去；改配置失败会把插件撤回。
- 输入框里粉色的访问模式按钮、绿色的模型按钮是作者特意保留的（喜欢鲜艳、花哨的风格），不需要为了统一配色降低饱和度。
- 代码也采用 CC BY-NC-SA 4.0：作者的选择（与角色原作一致），不是疏忽。
- `tools/combo_hair.py`、`tools/combo_relight*.py`、`tools/layered_mock.py`、`assets/relit/` 等是不再使用的旧工具和素材，可以忽略。

## 五、希望的输出格式

每个问题一条，按严重程度从高到低：

```
[严重 / 一般 / 轻微] 文件:行号
问题：一句话说明
触发条件：什么情况下会出问题（尽量具体，给出输入或操作步骤）
后果：会发生什么
建议修改：怎么改（可以给代码）
把握：确定 / 比较确定 / 不确定
```

只列有具体触发条件的问题；纯风格偏好、「可以考虑」之类的建议请单独放在最后，或者不写。没有发现问题的部分也请说明「看过，未发现问题」。
