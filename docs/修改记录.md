## 〇、动手之前：先备份

**任何改动之前都先备份**，包括改代码、换素材、让 Codex 或 GPT 往 `assets/` 里放图、重新安装。改崩了可以一键还原。

```bash
node tools/backup.mjs 改之前的说明        # 备份，标签随意，比如「接入桌子素材前」
node tools/backup.mjs --list              # 查看已有备份
node tools/backup.mjs --restore <目录名>   # 还原，然后重启 DeepSeek Harness
```

每份备份放在 `backup/<标签>-<时间>/`，包含两部分：

- `project/`：本项目的源码、文档、配置和素材（不含构建时会自动重新生成的 `*.maxN.png` 缓存图）。
- `profile/`：已安装到应用里的插件目录，以及 `cordis.patch.yml` 加载配置。

还原时：

- 会**先自动备份一次当前状态**（标签 `before-restore`），所以还原本身也能撤销。
- 代码和文档目录会整体替换成备份时的样子。
- 素材只覆盖、不删除，备份之后新加的图片会保留。
- 已安装的插件和加载配置会一起恢复。

一份备份约 70 MB，主要是素材。旧备份不需要时可以手动删掉 `backup/` 下对应的目录。`backup/` 只在本机使用，**分享给别人时不要带**。

## 一、给其他人：如何复现这套皮肤

### 前提

- macOS，已安装 DeepSeek Harness（`/Applications/DeepSeek Harness.app`）。
- Node.js 22 或以上（需要内置的 `fetch` 和 `WebSocket`）。
- Python 3 + Pillow（构建时用来缩放图片：`python3 -m pip install Pillow`）。

### 步骤

0. **先备份对方电脑上已有的东西**（如果对方以前装过别的本地插件）：把 `~/.dsh/profiles/desktop/cordis.patch.yml` 和 `~/.dsh/profiles/desktop/node_modules/@local/` 复制一份到别处。`install.mjs --apply` 第一次运行时也会自动把原插件快照存到项目的 `backup/ui-skin-original-20260930/`。
1. 拿到本项目目录（`dsh-logo/`）。**不需要** `backup/`、`build/`，也不要带别人电脑上的 profile。
2. 确认素材有再分发授权。没有的话，让对方自己准备同规格的图片放进 `assets/`。
3. 在项目目录运行：

   ```bash
   node tools/build.mjs
   node tools/verify.mjs
   node tools/install.mjs --apply
   ```

4. 完全退出 DeepSeek Harness 再打开。插件只在应用启动时加载。
5. 想恢复原样：点侧栏的「原版」按钮临时切回原生界面；或者运行 `node tools/install.mjs --revert` 后重启，完全卸载插件。

### 不想敲命令：纯复制安装

对方只想用、不打算改的话，可以不装 Node 和 Python，直接复制已构建好的插件：

0. 先把对方的 `~/.dsh/profiles/desktop/cordis.patch.yml` 复制一份备用。如果 `~/.dsh/profiles/desktop/node_modules/@local/dsh-logo/` 已经存在，也整个复制一份。
1. 把本项目 `brand-override/` 里的这三样复制到对方电脑的 `~/.dsh/profiles/desktop/node_modules/@local/dsh-logo/`（没有这个目录就新建）：
   - `package.json`
   - `index.js`
   - `dist/`（里面是 `client.js`，图片都已内联在里面）
2. 用文本编辑器打开 `~/.dsh/profiles/desktop/cordis.patch.yml`，在文件末尾追加这几行（缩进必须是空格）：

   ```yaml
   # Local logo override. Added by dsh-logo/tools/install.mjs; remove with --revert.
   - insert:
       - id: local-dsh-logo
         name: ./node_modules/@local/dsh-logo/index.js
   ```

3. 完全退出 DeepSeek Harness 再打开。

卸载：删掉上面那个插件目录和追加的几行，再重启应用。`~` 是用户主目录；在访达里按 `Cmd+Shift+G` 输入路径即可打开，`.dsh` 是隐藏目录。

### 什么时候需要改代码

- **只是使用**：不用改任何代码，复制文件或运行安装命令就行。脚本里没有写死的个人路径，都按当前用户的主目录计算。
- **想换图或改文案**：只改 `assets/` 里的图片和 `logo.config.json`，然后重新运行安装命令。
- **想改布局和样式**：改 `brand-override/skin.css`。
- **对方的 Harness 版本和这里不同**：界面结构可能变了，部分样式会失效，需要按「三、调试方法」检查选择器。本皮肤基于 2026-09 至 10 月的 DeepSeek Harness 桌面版制作。

安装脚本只写两处，都在用户目录里，**不修改应用本体和签名**：

- `~/.dsh/profiles/desktop/node_modules/@local/dsh-logo/`：插件文件。
- `~/.dsh/profiles/desktop/cordis.patch.yml`：追加一行插件加载项。

### 原理（一句话）

Harness 支持本地客户端插件。本插件做三件事：

1. 用较低优先级「遮蔽」官方的品牌图标插槽。
2. 通过主题服务覆盖颜色 token。
3. 往页面注入一份样式表和右侧陪伴栏。

所有聊天、模型选择、输入框都仍是 Harness 原生组件，皮肤只改外观。

## 二、文件分工

| 文件 | 作用 | 什么时候改 |
| --- | --- | --- |
| `brand-override/skin.css` | **所有布局和样式**。`$SKIN` 在构建时展开为 `html body[data-dsh-anime-skin="active"]` | 调位置、尺寸、颜色、层级 |
| `brand-override/skin-art.css` | 素材装饰层：九宫格边框、星饰、侧栏道具、桌子。每段 `/* @art key */ … /* @end */` 只在 `skin.art.key` 配置了素材时才生效 | 调素材的位置、大小、切片 |
| `assets/ui/` | GPT 生成的装饰素材（边框、星星、侧栏道具、桌子） | 换装饰图 |
| `brand-override/client.js` | 插件逻辑：皮肤开关、快捷键、侧栏文案替换、右侧陪伴栏和表情切换、颜色 token | 改文案、交互、加新的 DOM 元素 |
| `logo.config.json` | 素材路径、表情列表与气泡文案、包体上限 | 换图、加表情 |
| `tools/build.mjs` | 把素材内联成 data URI，与 skin.css 一起打包成 `dist/client.js` | 加新的素材槽位 |
| `tools/verify.mjs` | 不开浏览器的自检：结构、层级、关键选择器 | 改了布局规则后同步更新 |
| `tools/install.mjs` | 安装 / 卸载 / 恢复原插件 | 一般不用改 |
| `tools/devtools.mjs` | 连接运行中的应用：执行 JS、截图、实时注入 CSS | 调试用 |
| `tools/expressions.py` | 表情立绘自检（只允许改脸部区域）和统一裁切缩略图 | 接收新表情图时 |
| `tools/backup.mjs` | 备份 / 列出 / 还原（项目文件 + 已安装插件） | **每次改动前** |

## 三、调试方法（推荐流程）

改样式时不必每次「构建 → 安装 → 重启」。可以先在运行中的应用里实时试：

```bash
# 0. 先备份
node tools/backup.mjs 调样式前

# 1. 带调试端口启动（只监听 127.0.0.1）
osascript -e 'quit app "DeepSeek Harness"'
open -a "DeepSeek Harness" --args --remote-debugging-port=9333

# 2. 查看 DOM、截图
node tools/devtools.mjs eval "document.querySelector('[data-composer-card]').getBoundingClientRect().width"
node tools/devtools.mjs shot /tmp/dsh.png

# 3. 改 skin.css → 构建 → 实时注入预览（不用重启）
node tools/build.mjs && node tools/devtools.mjs live

# 4. 满意后正式验证、安装，并正常重启（关掉调试端口）
node tools/verify.mjs && node tools/install.mjs --apply
osascript -e 'quit app "DeepSeek Harness"' && open -a "DeepSeek Harness"
```

调试端口开着时，本机任何程序都能操控这个应用。调完一定要正常重启一次。

## 四、踩过的坑（改之前先看）

| 现象 | 原因 | 正确做法 |
| --- | --- | --- |
| 会话列表整片消失 | 旧逻辑按文字「默认工作区」给元素打隐藏标记；列表为空时，容器的文字恰好也是这几个字，于是整个列表被藏掉 | 不按文字匹配，按属性隐藏：`[role="treeitem"][data-row-key^="workspace:"]` |
| 草稿会话变成一个大蓝按钮 | 新会话的标题叫「新会话」，和「新建会话」按钮的文字一样，被侧栏的文字替换逻辑误认 | 文字替换时跳过会话树内部和包含会话行的元素 |
| 输入框装饰框错位、穿过文字 | 九宫格图配合固定宽度 `calc(100vw - 520px)`，和原生容器宽度不一致 | 输入框用 `width: 100%` 跟随容器；装饰改为纯 CSS 描边 + 星饰 |
| 输入框塌成一条竖线 | 父容器是居中的 flex 布局，`width: auto` 会被压缩 | 用 `width: 100%` + `box-sizing: border-box` |
| 侧栏收起后找不到展开按钮 | 收起后，原生「打开侧边栏」按钮移到顶栏左侧的按钮区（z-index 15）；对话列被设成 z-index 20，把它盖住了 | 对话列 z-index 设为 1；侧栏收起（`[data-sidebar-collapsed="true"]`）时撤掉卡片的外边距和边框 |
| 弹出菜单可能被人物挡住 | 原生弹出菜单层是 z-index 20，陪伴栏原先是 25 | 陪伴栏降到 12 |
| 右侧面板打开后布局错乱 | 陪伴栏和原生右侧面板（文件 / 终端 / 浏览器）重叠 | 只有 `[data-rightbar-collapsed="true"]` 时才显示陪伴栏，并给对话列留出右侧空间 |
| 「原版」按钮压住标题 | 原先用 `position: fixed` 固定在窗口坐标 | 挂进侧栏品牌行，侧栏收起时随之隐藏；DOM 重渲染后由 MutationObserver 重新挂载 |
| 圆形头像显示成圆角方形 | 原生给这个元素设了 `corner-shape: superellipse(1.5)`（超椭圆圆角） | 加 `corner-shape: round !important` |
| 头像被裁切 | 品牌行外层 `overflow: hidden` | 对品牌行及其外层设 `overflow: visible` |
| 新会话页「预览版」徽标看不清 | 皮肤把文字色改成深蓝，徽标底色本身是深色 | 单独给 `[class*="previewBadge"]` 设浅色文字 |
| 右侧面板展开后，压到对话框的边框 | 原生右侧面板的宽度写死为整列宽度（576px），再加外边距就向左溢出 | 面板宽度设为 `calc(100% - 21px)`（扣掉左右外边距） |
| 右侧面板里多出一条竖线 | 内容区原生自带 0.5px 左分隔线，加了内边距后显露出来 | 隐藏 `[data-sidebar-right-panel] [class*="tabHost"]` 的左边框 |
| 边框花饰压住标题和按钮 | 对话框边框四角的花饰向内伸约 46px | 顶栏左右各留 46px 内边距；右侧面板左右留 26px |
| 九宫格边框切歪了 | `border-image-slice` 用的是原图像素，图片被构建脚本缩小后数值就不对了 | 三张边框图不设 `maxPx`；构建脚本检测到被缩小会直接报错 |
| 深色系统下菜单、卡片、标签页变成深底深字 | 这些组件各自带有 `body[data-ds-dark-theme]` 深色规则，皮肤只改全局颜色变量，盖不住 | 皮肤开启时注册并选中一个浅色自定义主题（不持久化），关闭时恢复原偏好 |
| 页面上多了一层白色半透明背景 | 右侧面板关闭后元素仍在，全屏样式没限定「打开时」 | 规则加上 `[data-sidebar-right-open="true"]`，并按 `push` / `fullscreen` 分开写 |
| 全屏面板像半透明，底下内容透出来 | 对话列和侧栏的层级高于右侧面板列 | 全屏时右侧面板列 z-index 18，底色不透明 |
| 实时注入的样式不生效 | 已安装插件的样式在 body 里，排在注入到 head 的样式之后，同等优先级时后者输 | 涉及覆盖已有规则时，直接构建、安装、重启验证 |
| 搭在桌上的手指和袖口半透明 | 给立绘底部加了渐隐遮罩，想藏截断线，但立绘下沿本来就有完整轮廓 | 不加遮罩；接入新立绘前先看底部几行的不透明宽度是否逐行收窄 |
| 角色周围一圈灰色光晕 | 立绘的 18px 柔和投影叠在浅色对话框上 | 立绘不加投影 |
| 侧栏右侧金边缺一截 | 卡片宽度等于列宽，又有左边距，超出部分被列裁掉 | 卡片宽度扣掉左右边距；展开时列设 `overflow: visible` |
| 原版下看不到皮肤切换按钮 | 按钮伸出品牌行，原版的品牌行会裁切溢出 | 品牌行在两种模式下都设 `overflow: visible` |
| 后台启动时按钮和侧栏文案迟迟不出现 | `requestAnimationFrame` 在窗口隐藏时暂停 | 节流改用 `setTimeout` |
| 对话框和输入框边缘露出白底 | 白底按元素矩形圆角铺满，但金框的形状不同（四角卷边、两端半圆） | 白底放到单独一层，内缩到金框内线以内 |
| 点输入框后金框外出现蓝色线框 | 原生焦点样式改的是元素边框，而白底和金框都已内缩 | `:focus-within` 时撤掉原生边框，焦点提示画在白底内侧 |
| 窗口在后台时测不出焦点样式 | 窗口没有系统焦点，`focus()` 不生效 | 用 CDP `Emulation.setFocusEmulationEnabled` 模拟焦点 |
| 对话框四角卷边处露白 | 白底是圆角矩形，金框四角却是向内卷的弧形 | 从边框图内部泛洪填充生成遮罩，按同一套九宫格参数裁切白底 |
| 设置弹窗选中项深底深字 | 弹窗导航用的是侧栏的颜色变量，皮肤把它们设成了深蓝 | 在 `[role="dialog"]` 内把这几个变量改回浅色 |
| 素材里有不想要的描边 | 生成图自带的装饰线 | 按颜色找连通区域，只删跨度大的那条线，保留同色的小装饰 |
| 系统 Python 的 scipy 报 `IterAllButAxis` 错 | 本机 miniconda 的 scipy 和 numpy 版本不兼容 | 改用纯 Python 的广度优先填充，不依赖 scipy |
| 去掉素材里的线条后出现锯齿 | 直接把像素改成全透明，丢了原图的抗锯齿过渡 | 改成重新着色（按亮度映射到目标色），不删像素 |
| 九宫格边框发糊 | 原图的切片尺寸小于实际显示的物理像素（Retina 下要乘 2） | 生成素材时按「显示尺寸 × 2」以上的精度出图 |
| 模型输出时可能卡顿 | 每次 DOM 变化都全量扫描页面 | MutationObserver 回调用 `requestAnimationFrame` 节流，每帧最多扫描一次 |
| 改了插件却没生效 | 应用在安装之前就启动了 | 插件只在启动时加载，安装后必须重启应用 |

**选择器原则**：优先使用 Harness 的 `data-slot`、`data-*`、`role`、`aria-*` 属性，配合 `:has()` 定位。不要依赖 `_3WPZCG_root` 这类哈希类名，应用更新后它们会变。常用定位：

| 区域 | 选择器 |
| --- | --- |
| 侧栏卡片 | `div:has(> div > [data-slot="sidebar.workspaces"])` |
| 对话列 | `div:has(> [data-slot="main"])` |
| 对话面板（含顶栏） | `div[data-phase]:has(> [data-conversation-content])` |
| 输入框 | `[data-composer-card]`、`[data-composer-input]` |
| 侧栏品牌行 | `div:has(> span > span > span > [data-slot="sidebar.brand.mark"])` |
| 布局状态 | `[data-sidebar-collapsed="true"]`、`[data-rightbar-collapsed="true"]` |
| 右侧面板 | `[data-sidebar-right-panel][data-sidebar-right-open="true"]` |

**层级表**：全景背景 0 < 对话列 1 < 侧栏 10 < 陪伴栏 12 < 原生顶栏按钮区 15 < 原生弹出菜单层 20。新加的元素不要超过 15。
