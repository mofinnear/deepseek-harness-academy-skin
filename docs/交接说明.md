# 星海书院皮肤 · 交接说明（给新会话 / Codex）

> 更新于 2026-10-02。新开会话时先读这一份，再按需查 `docs/修改记录.md`（完整历史与踩坑表）。
> 文中路径都相对于本项目根目录（`dsh-logo/`）；`<素材目录>` 是用户存放 GPT 生成图的目录。

## 1. 这是什么

DeepSeek Harness 桌面版（Electron）的**本地皮肤插件**，非官方，只改外观，不改应用本体和签名。
目标外观以 `docs/reference/效果图.webp`（GPT 概念图）为准：全窗口书院夜景背景 + 左侧深蓝侧栏 + 中间金边对话框 + 底部胶囊输入框 + 右侧角色陪伴栏（立绘、书桌、对话气泡、四个表情）。

- 已发布 **v1.0.0**：GitHub `mofinnear/deepseek-harness-academy-skin`（公开），Release 附件 `dsh-academy-skin-v1.0.zip`。
- v1.0 之后的改动都已在本地 git 提交，**尚未推送**，等用户说要发新版时再推送（可发 v1.1）。

## 3. 每次改动的固定流程（必须遵守）

1. **先备份**：`node tools/backup.mjs <说明>`（备份项目文件 + 已安装插件；`--list` 查看，`--restore <目录>` 还原）。
2. 修改（样式改 `brand-override/skin.css` / `skin-art.css`，逻辑改 `brand-override/client.js`，素材路径改 `logo.config.json`）。
3. `node tools/build.mjs && node tools/verify.mjs`（必须全部通过；当前 73 项）。
4. `node tools/install.mjs --apply`，然后**完全退出并重新打开** DeepSeek Harness（插件只在启动时加载）。
5. 截图核对（见第 6 节调试方法）。
6. 在 `docs/修改记录.md` 的「五、版本记录」最上面追加一条：改了什么、为什么、怎么验证、备份目录；新踩的坑追加到踩坑表。
7. `git commit`（仓库本地身份：`mofinnear` / GitHub noreply 邮箱；全局 git 配置是坏的，不要用也不要改）。提交信息末尾加 `Co-Authored-By` 行。
8. 公开发布前：文档里不能有本机绝对路径；截图里的账号昵称、头像、会话标题要打码。

## 4. 代码结构

| 文件 | 作用 |
| --- | --- |
| `brand-override/skin.css` | 基础布局与样式。`$SKIN` 构建时展开为 `html body[data-dsh-anime-skin="active"]` |
| `brand-override/skin-art.css` | 素材装饰层。每段 `/* @art key */ … /* @end */` 只有 `logo.config.json` 的 `skin.art.key` 配了 source 才生效 |
| `brand-override/client.js` | 插件逻辑：皮肤下拉菜单（`SKINS` 列表）、快捷键、侧栏文案替换、陪伴栏与表情、浅色主题注册、用户头像、输入框高度观测 |
| `logo.config.json` | 素材路径、表情列表与气泡文案、包体上限（6 MB） |
| `tools/build.mjs` | 内联素材（可选 `"webp": true` 转有损 WebP）+ 拼样式 → `brand-override/dist/client.js` |
| `tools/verify.mjs` | 不开浏览器的自检 |
| `tools/install.mjs` | 安装到 `~/.dsh/profiles/desktop`（`--apply` / `--revert` / `--restore-original`） |
| `tools/backup.mjs` | 备份 / 还原 |
| `tools/devtools.mjs` | 连接调试端口：`eval` / `shot` / `css` / `live` |
| `tools/expressions.py` | 表情立绘自检（`check` 只改脸、`pose` 允许换姿势）与统一裁缩略图（`thumbs`） |

关键机制：
- **浅色主题**：皮肤开启时注册并选中一个不持久化的浅色主题 `@local/dsh-logo:academy-light`，关闭皮肤时恢复用户原来的主题偏好（系统深色模式下也不会出现深底深字）。
- **层级**：全景背景 0 < 对话列 1 < 侧栏 10 < 侧栏装饰 11 < 陪伴栏 12 < 原生顶栏按钮区 15 < 全屏右侧面板 18 < 原生弹出菜单 20。新元素不要超过 15。
- **选择器原则**：用 `data-slot`、`data-*`、`role`、`aria-*` + `:has()`，不要用会变的哈希类名。常用定位见 `docs/修改记录.md` 第四节。

书桌的对齐方式（重要）：
- `desk-v4.png`（1200×1800）是 GPT 先画「角色 + 书桌」合成图、再去掉角色得到的，**前 1312 行与立绘（1199×1312）逐像素对应**；桌面后沿 y≈1142，立绘前臂到 y≈1297。
- 立绘与书桌共用 `--dsh-ch-h`（= 63vh − 70px）缩放、`--dsh-ch-x` 水平定位（在 `skin-art.css` 的 `@art desk` 段）。**换书桌时必须保持同样的画布尺寸和角色位置**，否则对不齐。

## 6. 调试方法

```bash
osascript -e 'quit app "DeepSeek Harness"'
open -a "DeepSeek Harness" --args --remote-debugging-port=9333   # 只监听本机
node tools/devtools.mjs shot /tmp/dsh.png                         # 截图
node tools/devtools.mjs eval "<JS>"                               # 查 DOM
```
- 调完一定要正常重启一次（`open -a "DeepSeek Harness"`），关掉调试端口。
- 实时注入的样式会被已安装插件的样式覆盖，涉及覆盖已有规则时直接构建、安装、重启验证。
- 窗口在后台时测焦点样式要用 CDP `Emulation.setFocusEmulationEnabled`。
