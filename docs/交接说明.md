# 星海书院皮肤 · 交接说明（给新会话 / Codex）

> 更新于 2026-10-05。新开会话时先读这一份，再按需查 `docs/修改记录.md`（完整历史与踩坑表）。
> 文中路径都相对于本项目根目录（`dsh-logo/`）；`<素材目录>` 是用户存放 GPT 生成图的目录。

## 1. 这是什么

DeepSeek Harness 桌面版（Electron）的**本地皮肤插件**，非官方，只改外观，不改应用本体和签名。
目标外观以 `docs/reference/效果图.webp`（GPT 概念图）为准：全窗口书院背景（白天通透版） + 左侧深蓝侧栏 + 中间金边对话框 + 底部胶囊输入框 + 右侧角色陪伴栏（立绘、书桌、对话气泡、四个表情）。

- 已发布 **v1.1.1**（2026-10-05，修了切换会话时输入框缩一下 / 往上顶一下；v1.1.0 同日发布）：GitHub `mofinnear/deepseek-harness-academy-skin`（公开），Release 附件 `dsh-academy-skin-v1.1.1.zip`（= `tools/package_share.sh` 生成的安装包改英文名；GitHub 会弄乱中文附件名）。上一版 v1.0.0。
- 授权：全部内容 CC BY-NC-SA 4.0（与原作一致），二创声明和出处链接见 `LICENSE`。
- 支持 macOS 和 Windows（Windows 按应用代码适配，未在实机验证）。分享包里有一键安装 / 卸载脚本和写给 AI 助手的安装步骤（用户一般把 `使用说明.md` 交给 DeepSeek Harness 安装）。

## 3. 每次改动的固定流程（必须遵守）

1. **先备份**：`node tools/backup.mjs <说明>`（备份项目文件 + 已安装插件；`--list` 查看，`--restore <目录>` 还原）。
2. 修改（样式改 `brand-override/skin.css` / `skin-art.css`，逻辑改 `brand-override/client.js`，素材路径改 `logo.config.json`）。
3. `node tools/build.mjs && node tools/verify.mjs`（必须全部通过；当前 72 项；包体上限 8 MB）。
4. `node tools/install.mjs --apply`，然后**完全退出并重新打开** DeepSeek Harness（插件只在启动时加载）。
5. 截图核对（见第 6 节调试方法）。
6. 在 `docs/修改记录.md` 的「五、版本记录」最上面追加一条：改了什么、为什么、怎么验证、备份目录；新踩的坑追加到踩坑表。
7. `git commit`（仓库本地身份：`mofinnear` / GitHub noreply 邮箱；全局 git 配置是坏的，不要用也不要改）。提交信息末尾加 `Co-Authored-By` 行。
8. 公开发布前：文档里不能有本机绝对路径；截图里的账号昵称、头像、会话标题要打码。

## 4. 代码结构

| 文件 | 作用 |
| --- | --- |
| `brand-override/skin.css` | 基础布局与样式。`$SKIN` 构建时展开为 `html body[data-dsh-anime-skin="active"]` |
| `brand-override/skin-art.css` | 素材装饰层。每段 `/* @art key */ … /* @end */` 只有 `logo.config.json` 的 `skin.art.key` 配了 source 才生效 |
| `brand-override/client.js` | 插件逻辑：皮肤下拉菜单（`SKINS` 列表）、快捷键、侧栏文案替换、陪伴栏与表情、浅色主题注册、用户头像、输入框高度观测 |
| `logo.config.json` | 素材路径、表情列表与气泡文案、包体上限（8 MB） |
| `tools/build.mjs` | 内联素材（可选 `"webp": true` 转有损 WebP）+ 拼样式 → `brand-override/dist/client.js` |
| `tools/verify.mjs` | 不开浏览器的自检 |
| `tools/install.mjs` | 安装到 `~/.dsh/profiles/desktop`（`--apply` / `--revert` / `--restore-original`） |
| `tools/backup.mjs` | 备份 / 还原 |
| `tools/devtools.mjs` | 连接调试端口：`eval` / `shot` / `css` / `live` |
| `tools/sidebar_starmap.py` | 生成侧栏星图底纹 SVG（参数见 `skin.css` 注释） |
| `tools/combo_relight.py` | 角色 + 书桌合成图重新打光（自检 `tools/combo_relight_check.py`） |
| `tools/char_layers.py` | 第九步人物层（relit3 立绘 → `assets/combo/char-*.png`、缩略图）和固定书桌、前景层 |
| `tools/expressions.py` | 表情立绘自检（`check` 只改脸、`pose` 允许换姿势）与统一裁缩略图（`thumbs`） |

关键机制：
- **浅色主题**：皮肤开启时注册并选中一个不持久化的浅色主题 `@local/dsh-logo:academy-light`，关闭皮肤时恢复用户原来的主题偏好（系统深色模式下也不会出现深底深字）。
- **层级**：全景背景 0 < 对话列 1 < 侧栏 10 < 侧栏装饰 11 < 陪伴栏 12 < 原生顶栏按钮区 15 < 全屏右侧面板 18 < 原生弹出菜单 20。新元素不要超过 15。
- **选择器原则**：用 `data-slot`、`data-*`、`role`、`aria-*` + `:has()`，不要用会变的哈希类名。常用定位见 `docs/修改记录.md` 第四节。

**陪伴栏的结构（固定书桌 + 人物层，重要）**——`skin.mascot.desk`/`front` 给出时陪伴栏和 `[data-dsh-academy-desk-back]` 都带 `data-layered`：
- **素材全部由 `tools/char_layers.py` 生成**，完整命令（`<素材目录>` 是用户存放生成图的目录）：
  ```
  python3 tools/char_layers.py --src <素材目录>/round6/relit3 --override <素材目录>/round21 --desk <素材目录>/round15/desk-fixed.png \
    --shade-from <素材目录>/round18 --inputs <素材目录>/round17/输入 \
    --edit-from <素材目录>/round20 --edit-base <素材目录>/round19
  ```
  - 人物：relit3 立绘原图（2398×2624），两侧头发不再在桌沿切掉（`CUT_SIDE_HAIR = False`）。用户修过的立绘按同名放进新 round，用 `--override` 优先使用（现在 round21 有默认表情：右手边改成蓝色头发；注意用户这次是在 round6 原图上直接改后另存，round6 那张也已是修改后的版本）。
  - 桌面阴影一直延伸到人物下面（被人物盖住），换表情时人物往上顶 3px 才不会露出白边。
  - 摆放：脚本顶部 `FIG_X, FIG_Y = 230, −17`、`FIG_SCALE = 0.96`（合成图坐标 = 1405 宽书桌图左移 250），`CANVAS_DY = 27` 只用于给 GPT 的输入图。改这几个数要同步改 `skin.css` 人物层的 top/left/width/height（换算写在注释里）。
  - 人物贴桌部分的明暗取自 GPT round18（`--shade-from`，按书桌轮廓拟合对齐、比值搬运）；用户 PS 手加的袖子阴影取自 round20 相对 round19（`--edit-from/--edit-base`）；左侧冷白窗光由 `rim_light` 程序画（参数 `RIM_*`，照 GPT round19 的样子）。
  - 桌面阴影 `shadow-*.png`：**按 relit3 轮廓生成**（手臂、手、袖子，不含头发），颜色 `CONTACT_TINT`/`BROAD_TINT` 取自 GPT；不用 GPT 的比值（会把 GPT 画走样的头发、书页变成灰块）。
  - 书桌 `desk-fixed.png` 存整张（裁掉左段的话启动时能看到书桌被切断）；前景 `desk-front.png` 只取羽毛笔和墨水瓶的形状（`INKWELL`、`QUILL_SHAFT` 多边形）。
  - 给 GPT 的输入图：加 `--compose <目录>` 生成 `compose-*.png` 和 `mask-*.png`。
- **页面层次**（`client.js`、`skin.css` 合成图段）：每个表情一组 `.dsh-academy-pose` = 书桌（截在栏内）→ 桌面阴影（正片叠底，截在栏内）→ 人物（不截，头发伸出栏外）→ 羽毛笔墨水瓶；切换时新的一组 220ms 完整淡入，旧的再淡出。对话框下面的 `[data-dsh-academy-desk-back]`（z-index 0）只放一张书桌、不切换，显示陪伴栏左边以外的部分。整组再左移 0.1304 × 立绘宽，让耳朵和头发搭到对话框上（上限：左手肘不能越过栏边）。
- 气泡：`top = 104px + 0.9802 × 立绘高 + 8px`（墨水瓶下面）。

以下是旧的整张合成图做法，作为退路保留：
- `logo.config.json` 的 `skin.mascot.combo: true` 打开合成图模式；`skin.art.desk` 关掉。
- 素材 `assets/combo/`：`combo-*.png` 是 round14 合成图（1405×1120）裁出的 x 250–1250（1000×1120）；`thumb-*.png` 用同一个头部框裁；`hair-*.png` 是左侧一条只有头发的图（`python3 tools/combo_hair.py` 生成，换图后要重跑）。
- 每个表情是一个 `.dsh-academy-pose`，包含三处图：陪伴栏里的合成图（截在栏内）和头发条（只显示栏左边以外，盖住对话框），以及 body 下 `[data-dsh-academy-desk-back]` 里的同一张合成图（z-index 0，在对话框下面，只显示栏左边以外，让桌子延伸到对话框下）。
- 尺寸按立绘高度 `--dsh-ch-h`（63vh − 70px）换算：合成图里角色相当于立绘缩小 0.465 倍，立绘框左上角在合成图 (424, −3)。人物横向位置有下限，保证桌沿附近的袖子在栏内。
- 切换：新的一层叠在上面淡入（150ms），旧的晚 70ms 淡出，300ms 后删除；陪伴栏创建时预解码全部图片。淡入不能用 requestAnimationFrame（窗口在后台时不触发）。

## 6. 调试方法

```bash
osascript -e 'quit app "DeepSeek Harness"'
open -a "DeepSeek Harness" --args --remote-debugging-port=9333   # 只监听本机
node tools/devtools.mjs shot /tmp/dsh.png                         # 截图
node tools/devtools.mjs eval "<JS>"                               # 查 DOM
```
- 调完一定要正常重启一次（`open -a "DeepSeek Harness"`），关掉调试端口。
- 实时注入的样式会被已安装插件的样式覆盖，涉及覆盖已有规则时直接构建、安装、重启验证。
- 窗口在后台时测焦点样式要用 CDP `Emulation.setFocusEmulationEnabled`。

## 8. 与 Codex / GPT 协作的经验

- ChatGPT 应用里的长话题会频繁断连、很慢，换新话题明显更快；提示词要自包含（绝对路径、规格、验收标准写全），并要求每完成一张就存盘。
- 在 ChatGPT 输入框里用电脑控制粘贴长文本时，换行会丢、行首「- 」会被自动编号；后台模式下剪贴板不可用。最好由用户自己粘贴提示词。
- GPT 改图常见问题：不按要求保留底图（会整张重画）、横向压缩、矩形补丁和拼接线、残留上一张的手和道具。每轮都要原尺寸放大检查，并用差值脚本量化。
- 生成的效果图预览：本地文件在内置浏览器里不能截图，localhost 端口需要用户批准；可以用调试端口把样式临时注入运行中的 DeepSeek Harness 截图（`devtools.mjs eval` 加一个 `<style>`），这样看到的就是实际效果。
